# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

CVAT (Computer Vision Annotation Tool) is a self-hosted data annotation platform for images, video,
and 3D point clouds. It is a **monorepo** with a Django REST backend, a React/TypeScript frontend split
across several Yarn workspaces, a Python SDK/CLI, and Docker-based deployment.

## Architecture

### Backend (`cvat/`) — Django + DRF

- `cvat/apps/` holds the server modules. Each is a standard Django app:
  - `engine` — the core: tasks, jobs, projects, annotations, data/media handling, chunking. Most domain logic lives here (`models.py`, `serializers.py`, `views.py`, `task.py`, `frame_provider.py`, `media_extractors.py`).
  - `iam` — authentication and authorization. **Authorization is enforced via Open Policy Agent (OPA)**, with policies written in Rego under `cvat/apps/*/rules/*.rego`. Permission classes in each app's `permissions.py` call into OPA.
  - `dataset_manager` — import/export of annotation formats (uses the `datumaro` library).
  - `quality_control`, `consensus` — annotation QA, ground-truth/honeypot, agreement between annotators.
  - `events`, `log_viewer` — analytics pipeline (events → ClickHouse via Vector → Grafana).
  - `lambda_manager` — serverless (Nuclio) auto-annotation functions.
  - `webhooks`, `organizations`, `health`, `redis_handler`, `access_tokens`, `dataset_repo`.
- `cvat/settings/` — split settings: `base.py`, then `development.py` / `production.py` / `testing.py`. Select with `--settings cvat.settings.<name>` or `DJANGO_SETTINGS_MODULE`.
- **Async work runs on RQ (Redis Queue) workers**, not in the request cycle. Long operations (import, export, annotation, quality reports, chunk generation, consensus, webhooks) are dispatched to dedicated worker queues — see the `cvat_worker_*` services in `docker-compose.yml`. `manage.py` and `rqworker.py`/`rqscheduler.py` are the entry points.
- The REST API schema is generated by **drf-spectacular** into `cvat/schema.yml`. This file is the source of truth for the SDK.

### Frontend — Yarn workspaces (see root `package.json` `workspaces`)

Layered, lower → higher:
- `cvat-data` — media (video/image) decoding.
- `cvat-core` — client-side domain library; **all server interaction goes through here** (the UI does not call the API directly).
- `cvat-canvas` / `cvat-canvas3d` — the 2D and 3D annotation canvas rendering.
- `cvat-ui` — the React + Redux + Ant Design application that composes the above.

### Python clients

- `cvat-sdk` — Python client library. The low-level `cvat_sdk.api_client` layer is **generated from `cvat/schema.yml`** (do not hand-edit it; regenerate via `cvat-sdk/gen/generate.sh`). Higher layers (`core`, `pytorch`, `auto_annotation`) are hand-written.
- `cvat-cli` — command-line client built on top of `cvat-sdk`.

## Commands

### Frontend (run from repo root)

```bash
yarn --immutable                 # install (uses Yarn 4 / Corepack; do NOT use Yarn Classic)
yarn run build:cvat-ui           # build a workspace (also build:cvat-core, :cvat-canvas, etc.)
yarn start:cvat-ui               # dev server with autorebuild (needs a running CVAT backend)
yarn run type-check              # tsc against cvat-ui/tsconfig.json
yarn lint                        # eslint .
yarn lint:fix                    # eslint . --fix
yarn workspace cvat-core run test
```

### Python formatting / linting

```bash
dev/format_python_code.sh        # applies black + isort (line length 100, py310 target)
```

Authorization (Rego) is linted/tested separately — see OPA section below.

### Backend server unit tests

Requires the `cvat_opa` container running (authorization decisions hit OPA) and a built server image:

```bash
pip install -r cvat/requirements/testing.txt
docker compose -f docker-compose.yml -f docker-compose.dev.yml build cvat_server
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d cvat_opa

python manage.py test --settings cvat.settings.testing cvat/apps -v 2
# single app / single test:
python manage.py test --settings cvat.settings.testing cvat/apps/engine -v 2 -k test_api_v2_projects_
```

### REST API / SDK / CLI tests (pytest, manages its own containers)

```bash
pip install -e ./cvat-sdk -e ./cvat-cli -r ./tests/python/requirements.txt
pytest ./tests/python                       # auto-starts the needed docker containers
pytest ./tests/python --rebuild             # rebuild CVAT images first
pytest ./tests/python --start-services      # just start containers, don't run tests
pytest ./tests/python --stop-services       # tear them down
pytest ./tests/python -k <expr>             # single test/file
```

Debugging: `CVAT_DEBUG_ENABLED=yes pytest --rebuild --start-services tests/python`, then attach via the VS Code tasks (`REST API tests: Attach to server`, `... Attach to RQ low/default`).

### End-to-end (Cypress) tests — `tests/`

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml \
  -f components/serverless/docker-compose.serverless.yml \
  -f tests/docker-compose.minio.yml -f tests/docker-compose.file_share.yml up -d
cd tests && yarn --immutable
yarn run cypress:run:chrome
yarn run cypress:run:chrome:canvas3d
```

Tested primarily against Chromium-based browsers.

### IAM / OPA (authorization) tests

```bash
python cvat/apps/iam/rules/tests/generate_tests.py     # regenerate test data
docker compose run --rm -v "$PWD:/mnt/src:ro" -w /mnt/src cvat_opa test -v cvat/apps/*/rules
# lint Rego with Regal:
docker run --rm -v ${PWD}:/mnt/src:ro -w /mnt/src ghcr.io/styrainc/regal:0.11.0 lint cvat/apps/*/rules
```

### Running the stack locally

```bash
docker compose up -d                                   # full stack
docker exec -it cvat_server bash -ic 'python3 ~/manage.py createsuperuser'
# UI at http://localhost:8080
```

Layer extra compose files for dev/optional features: `docker-compose.dev.yml` (debug, local source mounts),
`components/serverless/...` (Nuclio), `components/analytics/...`, `tests/docker-compose.minio.yml`, etc.

## Conventions

- **Python 3.10**, Black + isort (line length 100). The pinned `cvat/requirements/*.txt` files are generated from `*.in` files — edit the `.in` and regenerate (see `cvat/requirements/README.txt`), don't edit `.txt` by hand.
- **JS/TS**: Airbnb style **with 4-space indentation** (not 2). Enforced by `eslint.config.mjs`.
- **Changelog**: every user-facing change needs a fragment in `changelog.d/` (scriv format — see existing `changelog.d/*.md` and `scriv.ini`). CI runs `dev/check_changelog_fragments.py`.
- **Editing the API**: changing serializers/views changes `cvat/schema.yml`; the generated SDK layer (`cvat_sdk/api_client`) must be regenerated, not edited.
- **Authorization changes** mean editing the relevant app's `rules/*.rego` *and* its `permissions.py` — they work together.
- Main/PR branch is `develop`.
